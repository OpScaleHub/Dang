# 0.4 — "simple by default" redesign

Goal: a non-technical manager (the reference user is 60+ and has never used accounting software)
can set up a building and run a month **without help**, and testers can send **structured
feedback** from inside the app. Evidence and method: docs/10 (and the second-brain note
*ux-research-for-non-technical-users*). The formal sessions in docs/10 run with this version.

## The core change: ask how the building charges, then hide the engine

Iranian buildings charge in one of two ways, and the app never asked which:

| The manager says… | What the app sets up |
|---|---|
| «هر ماه یک مبلغ ثابت شارژ می‌گیریم» (fixed monthly charge; bills are paid from the pot) | A monthly charge per unit, per person or per m², and expense types that are **paid from the fund** by default, so bills are never charged twice |
| «هر ماه قبض‌ها را بین واحدها تقسیم می‌کنیم» (split the actual bills) | Expense types with everyday split defaults (water and cleaning by number of people, the rest equally) |

The setup wizard asks this in plain words. Everything else follows from the answer.

## Principles applied

| Principle (docs/10) | Concrete change |
|---|---|
| Match the user's model | The charging question above; «نوع هزینه» instead of «دسته»; split choices named by what they do («مساوی بین همه واحدها»، «به تعداد نفرات هر واحد»، «به متراژ»، «از صندوق ساختمان — به کسی شارژ نمی‌شود») |
| Information overload | New buildings start with **6** expense types (آب، برق و گاز مشاعات، نظافت، آسانسور، تعمیرات، سایر) instead of 13; the demo keeps its full set |
| Progressive disclosure | A **simple mode** (default) and an **advanced mode** (Settings). Simple hides the formula editor, rare menu items (change log, fixed-charge editor, parking and meters until used) and rare transaction actions |
| Recognition over recall | Expense form: tap the type, type the amount, pick how to split, and see each unit's share; description, date and month are filled in automatically |
| Older users: bigger, slower, forgiving | In-app **text size** (normal / large / larger) on top of Android's own; one decision per wizard step; nothing technical in the wizard (rounding, currency code, decimals live in advanced settings) |
| Users don't find updates | Update check on every start (at most hourly); the update card on every main tab |
| Design with users | **Feedback from inside the app** (below) |

## Built-in structured feedback

- **«نظر یا مشکل»** button in the top bar of every screen. It captures the current screen,
  then asks: what kind (مشکل / گیج شدم / پیشنهاد / خوب بود), «داشتید چه کاری می‌کردید؟»,
  «چه اتفاقی افتاد یا چه انتظاری داشتید؟». It sends a structured message plus the screenshot
  through the share sheet (Telegram, WhatsApp, email…) to whoever handed out the app. It
  includes the app version, Android version, phone model and screen name, and no building data
  except what the user chooses to include in the screenshot. It also tells the tester they can
  add a voice message in the messenger and use the phone's screen recorder.
- **«نظرسنجی کوتاه»** (the 10 SUS questions, docs/10) in «بیشتر»; offered once on Home after
  5 days of use. It sends the answers and the 0–100 score as text.

## Compatibility
No database or backup change. Existing buildings keep all their categories and data; simple mode
only hides controls and never changes data. Advanced mode shows everything as in 0.3.
